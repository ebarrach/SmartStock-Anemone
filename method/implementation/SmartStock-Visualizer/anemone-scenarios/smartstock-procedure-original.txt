============================================================
SMARTSTOCK — DÉMONSTRATION ANEMONE
Scénario : Deborah retire une boîte de compresses
============================================================

OBJECTIF
--------
Stock initial : 40 boîtes de compresses.

Un retrait n'est validé que si :
1. le capteur de poids détecte un changement ;
2. le lecteur NFC détecte la boîte.

Si les deux événements sont présents :
    → retrait confirmé
    → stock décrémenté automatiquement

Résultat attendu :
    stock(compresse,40)
              ↓
    stock(compresse,39)

============================================================
ÉTAPE 9 — EXPLIQUER L'AGENT AVANT DE CLIQUER RUN
============================================================

1.

get(poids_change(compresse))

→ L'agent attend/consomme l'événement provenant
  du capteur de poids.


2.

get(nfc_detecte(compresse))

→ L'agent attend/consomme la détection NFC.


3.

tell(retrait_confirme(compresse))

→ Puisque les deux capteurs concordent,
  le retrait est confirmé.


4.

sum q in Stock:

→ q représente la quantité actuelle.

Stock contient les valeurs possibles de 0 à 40.


5.

get(stock(compresse,q))

→ L'agent récupère la quantité actuellement
  présente dans le blackboard.

Dans notre démonstration :

    q = 40


6.

tell(stock(compresse,pred(q)))

→ On introduit le nouvel état du stock.

Comme :

    q = 40

et :

    pred(40)=39

on obtient :

    stock(compresse,39)

============================================================
PHRASE DE CONCLUSION
============================================================

"Le blackboard permet ici aux différents composants
du système de communiquer indirectement.

Les capteurs publient leurs événements dans
l'environnement partagé.

L'agent SmartStock ne confirme le retrait que lorsque
les informations du capteur de poids et du lecteur NFC
sont disponibles.

Il récupère ensuite dynamiquement la quantité q et
utilise pred(q) pour mettre à jour le stock.

La logique n'est donc pas limitée au passage de
40 à 39 : le même principe permet de gérer
39 vers 38, 38 vers 37, etc."
