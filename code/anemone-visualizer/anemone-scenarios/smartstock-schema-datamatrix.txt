============================================================
COMMENT LIRE LE SCHÉMA
============================================================

Les deux branches représentent des événements indépendants.
Un seul événement ne suffit pas à publier la confirmation.
Le chemin de l'agent reste séquentiel : le poids peut être consommé
avant l'arrivée du Data Matrix. En cas de blocage, garder l'AST.

AVANT : stock(compresse,40), poids_change(compresse),
        datamatrix_detecte(compresse), chacun avec multiplicité 1.
APRÈS : retrait_confirme(compresse) [1], stock(compresse,39) [1].

Un second retrait sur le même Blackboard peut produire :
        retrait_confirme(compresse) [2], stock(compresse,38) [1].

Les trois rôles :
    Frontend : visualisation, boutons, animations.
    Bridge Java : transport, orchestration, lecture des résultats.
    Anemone : exécution de l'agent et transformation du store.

Le motif Data Matrix affiché est illustratif. Les événements sont
déclenchés par les boutons, pas par un scanner physique intégré.
Se référer à smartstock-procedure-datamatrix.txt pour le tutoriel.
